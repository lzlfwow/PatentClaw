概览 · OVERVIEW

PatentClaw 是一款面向科研人员的论文转专利辅助工具🦞。上传一篇 LaTeX 论文， PatentGenerator 自动抽取技术要点并撰写出符合法定结构的技术交底书； PatentReviewer 再对照原文独立审校，给出评分与修订方案，产出可直接交给专利代理师的终版文档。 全程每一句技术表述都可追溯到论文原文，拿不到证据支持的内容绝不臆造。

PatentClaw turns a research paper into a patent-ready technical disclosure. PatentGenerator reads your LaTeX paper and drafts a legally structured disclosure; PatentReviewer then independently re-checks it against the original text, scores it, and produces a revised, filing-ready version. Every technical claim stays traceable to the paper — nothing is fabricated without evidence.

§ 1

核心特点

Features

PatentClaw 由两个通过文件契约协作的独立服务组成：PatentGenerator 负责生成，PatentReviewer 负责审校。两者共同保证的是同一件事——交底书里的每一句话都有出处。

01
证据可追溯
每条技术特征、每个实施例都映射回论文原文片段，找不到依据的内容不会被写进正文。
02
法定结构一次到位
直接产出符合专利代理惯例的 17 章节技术交底书，而不是照搬论文目录简单改写。
03
生成与审校双引擎
两个独立服务只通过文件与 HTTP 接口协作；审校侧不盲信生成侧的结论，会重新核查一遍。
04
版本化固定检查表
30 项检查覆盖 13 个维度，18 项由确定性规则执行、12 项由模型判定。维度与严重程度写死在检查表里，模型不能自行增删。
05
模型只做逐项判定
语义检查必须恰好返回全部 12 项，缺项、重复或未知 check_id 一律拒绝；模型不输出维度，也不自己定严重程度。
06
量化评分与分级
只对 fail 与 needs_human_review 的检查项按严重程度扣分，同一检查项即使影响多章也最多扣一次，是否通过由程序判定。
07
逐项隔离改稿
每个未通过项各起一个 Agent，只能改自己声明的字段、只能提交能唯一定位的局部替换，改完重跑整张检查表，默认最多三轮。
08
离线可复现
全链路支持离线模式，无需模型密钥即可验证。此时 12 项语义检查标记为 not_assessed，因此离线报告不会声称「整张检查表通过」。
§ 2

工作原理

How It Works

从一篇论文到一份可交底的终版文档，全程七步。每一步的真实产出可以在 §4 运行示例 里逐项对照。

STEP 01
提交论文
上传 LaTeX 论文（.tex 或工程 .zip），也可通过 CLI 直接处理本地文件。
STEP 02
解析并建立证据账本
抽取章节、公式、图表并逐条编号，为后续每一句技术表述提供可核查的出处。
STEP 03
自动撰写交底书
依次完成技术理解、发明点挖掘、方案重构与实施例组织，产出覆盖 17 个法定章节的初稿。
STEP 04
按固定检查表初审
PatentReviewer 对照原文重新核查：18 项确定性规则 + 12 项模型逐项判定，合并为一张 30 项检查表并算出初审分。
STEP 05
逐项隔离改稿
每个未通过的检查项各起一个改稿 Agent，只能改该项声明的字段。缺少原始技术事实时必须返回 blocked 并列出所需材料，不允许编造挂接点、参数或实验数据。
STEP 06
复检并循环
合并局部补丁后重跑整张检查表；仍有问题且本轮产生了安全修改就进入下一轮，默认最多三轮，一轮没有任何修改则提前停止。
STEP 07
导出终版
输出终版技术交底书（DOCX / Markdown / JSON）及初审、终审报告与逐项改稿记录，可直接交给专利代理师。

这个示例想说明什么

三轮逐项改稿里有 10 次返回 blocked——不是失败，而是系统拒绝在没有原始依据的情况下动笔， 转而写清缺哪些材料交还发明人。终审 40 分、判定未通过，剩下 6 项要的都是论文里没写、只有发明人知道的技术事实。 把不知道的事情标出来，而不是编一个让分数变好看的答案，是这套流水线的设计目标。

示例页同时记录了一处改稿引入的回归（UE-01 由通过变为待确认）和一个当前检查表发现不了的缺陷（终版导出丢失全部附图）， 没有隐去。

§ 5

快速开始

Quick Start

以下为 Windows PowerShell 环境。模型服务走 OpenAI 兼容接口，可指向内网部署。

PatentGenerator
# 安装与离线验证 cd PatentGenerator python -m venv .venv .venv\Scripts\Activate.ps1 pip install -e ".[dev]" pytest -q # 离线跑通全流程（不调用模型 API） $env:L2D_OFFLINE_MODE="true" latex2disclosure examples\sample.tex # 在线模型模式 $env:L2D_OFFLINE_MODE="false" $env:OPENAI_API_KEY="你的服务端 Key" $env:L2D_MODEL="gpt-5.4-mini" $env:L2D_ENABLE_REVIEW="false" # 启动 API 服务 latex2disclosure-api # http://127.0.0.1:8100 · 文档 /docs
PatentReviewer
# 安装（约定装入已有 patentclaw Conda 环境） conda activate patentclaw cd PatentReviewer python -m pip install -e ".[dev]" pytest -q # 离线跑一次审查（不调用模型，仅确定性规则） patent-reviewer run ` --generator-job .\generator-task\artifacts\job.json ` --source .\paper.tex ` --output .\data # 在线模式：固定检查表审查 + 逐项隔离改稿 Copy-Item .env.example .env # 编辑 .env：PR_OPENAI_API_KEY / PR_OPENAI_BASE_URL / PR_OPENAI_MODEL # 改稿轮数上限，可取 1–10，默认 3 $env:PR_MAX_REVISION_ROUNDS="3" patent-reviewer run ` --generator-job .\generator-task\artifacts\job.json ` --source .\paper.tex ` --output .\data ` --online # 启动 API 服务（同步阻塞，无 CORS） patent-reviewer serve --host 127.0.0.1 --port 8011 # http://127.0.0.1:8011/health
说明

离线模式无需任何模型密钥即可验证全流程，但输出仅为结构验证级别，不可作为正式专利申请文件。当前仅支持 LaTeX 输入；创造性、新颖性、权利要求范围与侵权分析仍需专利代理师人工完成。
